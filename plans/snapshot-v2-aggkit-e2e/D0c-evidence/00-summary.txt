=====================

then publish a new image" (mirroring D0b's devnet conversion).

Mid-step, the user/orchestrator changed scope: "no, you need to update
kurtosis to work with the new config. Clean the old stuff for good." ->
delete the aggkitBridgeApis map form from the schema entirely, not just stop
using it in config.json. Two commits landed on feat/aggkit-backend as a
result:

  2da5992  feat(config): move mainnet and testnet onto aggkitProxy too
           (original scope: config.json's 3 modes -> aggkitProxy; schema
           still accepts the map form)
  8563dd4  feat(config)!: remove the aggkitBridgeApis map form entirely
           (scope-change: delete the map form, its schema field, its
           validator cross-checks, and the NEXT_PUBLIC_AGGKIT_BRIDGE_APIS
           env override; migrate every remaining consumer)

Also touched, not in the original ask but necessary consequences of "clean
the old stuff for good" (judgement calls, flagged for the record):
  - .github/workflows/deploy.yaml: NEXT_PUBLIC_AGGKIT_BRIDGE_APIS secret ref
    -> NEXT_PUBLIC_AGGKIT_PROXY (only runs on push to main/dispatch, not PR
    CI). If a real GH secret named NEXT_PUBLIC_AGGKIT_BRIDGE_APIS exists,
    an org admin needs to add NEXT_PUBLIC_AGGKIT_PROXY as its replacement.
  - playwright.config.ts: now requires NEXT_PUBLIC_AGGKIT_PROXY; the
    "partial-failure" project (which depended on a per-network bogus
    override only the retired map-form env var could express) was removed.
    tests/bridge/partial-failure.spec.ts is skipped with a comment
    explaining why and what a redesign would need -- flagged as a follow-up,
    not invented here.
  - .github/workflows/e2e.yaml: deliberately NOT touched (D1's territory).
    It still sets the retired NEXT_PUBLIC_AGGKIT_BRIDGE_APIS literal, which
    is why the e2e PR check fails (07). D1's own plan note already
    anticipated updating this literal for a related reason.
